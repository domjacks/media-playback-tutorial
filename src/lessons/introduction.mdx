## What This Course Is

This course teaches how media playback actually works, from the numbers that describe a single frame to the requests a streaming player makes every few seconds. It is written for software engineers: it assumes you can read JavaScript and use a terminal, but not that you know anything about video.

You learn by doing two things. You inspect real media files with FFmpeg and `ffprobe` until terms like GOP, `moov`, `tfdt` and edit list are things you have seen rather than things you have read about. Then you build small browser players, starting with a plain `<video>` element and ending with adaptive, live, low-latency, subtitled and encrypted playback.

The goal is not to rebuild dash.js, hls.js or Shaka Player. It is to understand what those libraries do on your behalf, so you can choose one, configure it, and debug it when playback fails.

## The Route Through The Course

The course has 41 lessons in 12 sections. Later sections build on earlier ones, so work through them in order.

- **Getting Started:** this lesson.
- **Media Fundamentals:** pixels, resolution, colour, frame rate and HDR; PCM audio, sample rate and channels; then a first FFmpeg lab.
- **Codecs And Containers:** why raw video is huge and how H.264-style compression works; MP4 boxes, codec strings, fragmented MP4 and CMAF, and the timestamps that tie samples to time. Four labs inspect real encodes.
- **Playback In The Browser:** the media element's timeline and buffers, progressive download, segments, and Media Source Extensions (MSE), from a first append to debugging and the full API.
- **DASH And Adaptive Streaming:** HLS and DASH compared, reading an MPD, a DASH parser, adaptive bitrate, buffer management, seeking and eviction.
- **HLS:** multivariant and media playlists, then an HLS player built on MSE.
- **Decoding With WebCodecs:** demuxing samples yourself and decoding them without MSE.
- **Live Streaming:** live edges and windows, DASH live timing and clock sync, and a live player.
- **Delivery And Quality:** HTTP and CDNs, quality-of-experience metrics and CMCD, and low-latency streaming with chunked fetch.
- **Subtitles:** WebVTT, TTML and IMSC, native text tracks and a custom renderer.
- **Encrypted Media:** EME, Common Encryption and DRM systems, then a working ClearKey player.
- **Wrap Up:** the in-app player that combines the pieces.

## How The Lessons Work

Lessons are marked Theory or Practical. Theory lessons explain the concepts and end with a prediction question: answer it before you reveal the answer. Practical lessons build on the theory before them.

Every practical lesson has a checkpoint: the complete code as it stands at the end of the lesson. The code in the lesson is taken from those files, so what you read is what runs.

- **Browser checkpoints** open from the lesson with "Open checkpoint". They are plain HTML and JavaScript modules with no build step.
- **Lab checkpoints** are `lab.sh` scripts that run FFmpeg and `ffprobe`. They create a `lab/` folder in the directory you run them from.
- **"You should now see"** lists what to check in the page, the console or DevTools before you move on.
- **An exercise** with a hint closes each practical lesson.

## What You Need

- **A desktop browser that plays H.264 and AAC:** current Chrome, Edge, Safari or Firefox. Some Linux Chromium builds ship without these codecs and cannot play the course streams. The WebCodecs lessons need a browser with WebCodecs, and the DRM player needs `localhost` or HTTPS.
- **FFmpeg 5 or later, with `ffprobe`,** for the labs. The labs were written against FFmpeg 8.
- **A Bash shell** to run the lab scripts: Linux, macOS, or WSL on Windows.
- **Node.js 20.19 or later** to run the site locally with `npm run dev`, and to run the box-walker script in the media timing lab.
- **Optional:** Bento4 (`mp4dump`) or GPAC (`MP4Box`) to dump MP4 box trees. The labs skip those steps if neither is installed.
- **Network access** to the public test streams: the BBC's Big Buck Bunny DASH stream, Apple's fMP4 HLS example, and the DASH-IF live simulator.

<Question prompt="A player shows a black frame and never starts. Using the section list above, which three sections would you look to first, and what would you check from each?">

Start with Playback In The Browser: check the media element's `readyState` and `error`, and whether `addSourceBuffer` or `appendBuffer` threw, because MSE failures stop playback before anything is decoded. Then Codecs And Containers: confirm the codec string the player declared matches the stream, and that an init segment was appended before any media segment. Then Delivery And Quality: look at the Network panel for failed or blocked segment requests, such as a 404 or a missing CORS header. Each section maps to a stage of the pipeline: fetch, then parse, then decode and present.

</Question>
